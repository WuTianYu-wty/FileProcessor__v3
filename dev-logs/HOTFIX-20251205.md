# 紧急修复日志 - 2025-12-05

## 🐛 发现的问题

### 问题 1: 批处理文件中文乱码
**症状**: 运行 `start-dev.bat` 时，中文显示为乱码
```
寮€鍙戠幆澧冨惎鍔?  (应该显示: 开发环境启动)
妫€鏌ュ悗绔緷璧?.. (应该显示: 检查后端依赖...)
```

**原因**: 
- Windows cmd 默认使用 GBK/GB2312 编码
- 文件使用 UTF-8 编码保存
- 编码不匹配导致中文乱码

### 问题 2: better-sqlite3 编译失败
**症状**: npm install 时报错
```
gyp ERR! find VS You need to install the latest version of Visual Studio
gyp ERR! find VS including the "Desktop development with C++" workload
```

**原因**:
- better-sqlite3@12.5.0 需要编译原生模块
- 需要 Visual Studio 构建工具（约 6GB）
- 用户系统未安装 Visual Studio

## 🎯 技术要点

### 编码问题解决思路

1. **问题根源**: Windows cmd 编码不一致
   - cmd 默认: GBK/GB2312
   - 现代工具: UTF-8

2. **解决方案**:
   - **方案 A**: 切换到 PowerShell（支持 UTF-8）
   - **方案 B**: 使用 GBK 编码保存批处理文件
   - **方案 C**: 使用英文界面（避免中文）
   - **方案 D**: 使用 `chcp 65001` 临时切换编码

3. **最佳实践**:
   - ✅ 使用 PowerShell 脚本（现代、功能强大）
   - ✅ 提供多个备选方案（兼容性好）
   - ✅ 文档中清晰说明各方案优缺点

### better-sqlite3 版本选择

1. **为什么不用最新版？**
   - 12.x 需要编译原生模块
   - 需要安装 Visual Studio（约 6GB）
   - 编译耗时且容易失败

2. **为什么选择 9.6.0？**
   - ✅ 提供预编译二进制文件
   - ✅ 支持 Windows/Linux/Mac
   - ✅ 安装快速，无需编译
   - ✅ 稳定性经过验证
   - ✅ 功能满足项目需求

3. **版本兼容性**:
