# 自定义地址与公司脱敏使用指南

## 📖 功能概述

FileProcessor v1.3.0+ 支持自定义地址和公司名称的脱敏功能，让您可以灵活保护特定的地理位置信息和企业信息，适用于企业文档处理、隐私保护、合规要求等场景。

---

## 🎯 适用场景

### 场景 1：企业内部文档处理
```
需求：处理员工合同，需要脱敏公司地址和名称
配置：
- 添加公司总部地址
- 添加各分公司地址
- 添加公司全称和简称

效果：保护公司地理信息不被外泄
```

### 场景 2：客户资料保护
```
需求：处理客户合同和订单
配置：
- 添加重要客户公司名称
- 添加客户办公地址
- 添加收货/发货地址

效果：保护客户隐私和商业信息
```

### 场景 3：合规要求
```
需求：满足数据保护法规要求
配置：
- 添加所有涉及的组织名称
- 添加所有具体地址信息
- 设置自动化脱敏流程

效果：符合 GDPR、CCPA 等法规要求
```

## 📊 脱敏规则说明

### 地址脱敏规则

**短地址（≤ 15 字符）**：
```
原文：北京市朝阳区建国路88号
脱敏：北京市朝阳区***8号
规则：保留前5个字符 + *** + 后3个字符
```

**长地址（> 15 字符）**：
```
原文：北京市朝阳区建国路88号现代城A座12层
脱敏：北京市朝阳区建***座12层
规则：保留前6个字符 + ****** + 后4个字符
```

### 公司脱敏规则

**短公司名（≤ 6 字符）**：
```
原文：某某公司
脱敏：某某***
规则：保留前2个字符 + ***
```

**长公司名（> 6 字符）**：
```
原文：某某科技有限公司
脱敏：某某科***司
规则：保留前3个字符 + *** + 最后1个字符
```

**示例**：
```
原文：北京某某网络科技股份有限公司
脱敏：北京某***司

原文：某某（中国）投资有限公司
脱敏：某某（***司
```

## 🎯 最佳实践

### 1. 地址配置建议

✅ **推荐做法**：
```
详细地址（包含门牌号、楼层）：
  北京市朝阳区建国路88号现代城A座12层

完整地址（便于精确匹配）：
  上海市浦东新区世纪大道1500号东方大厦25楼2501室

多个地址分开配置：
  - 公司总部地址
  - 各分支机构地址
  - 仓库/物流地址
```

❌ **避免**：
```
过于简短：
  北京市朝阳区 ❌（太泛化，可能误伤）
  
过于模糊：
  某某大厦 ❌（无法准确定位）
  
包含通配符：
  北京市*区 ❌（不支持通配符）
```

### 2. 公司配置建议

✅ **推荐做法**：
```
使用完整公司名称：
  某某科技有限公司
  某某集团股份有限公司
  
包含多种写法：
  - 某某科技有限公司（全称）
  - 某某科技（简称）
  - XX Tech Co., Ltd（英文名）
  
母子公司都配置：
  - 某某集团股份有限公司（母公司）
  - 某某（北京）科技有限公司（子公司）
```

❌ **避免**：
```
过于简短：
  某某 ❌（可能误伤普通词汇）
  
不完整：
  有限公司 ❌（太通用）
```

## ⚠️ 注意事项

### 1. 精确匹配

```
配置的地址/公司必须完全匹配才会脱敏

示例：
配置：北京市朝阳区建国路88号
原文：北京市朝阳区建国路88号 ✅ 会脱敏
原文：北京市朝阳区建国路 88 号 ❌ 不会脱敏（有空格）
原文：朝阳区建国路88号 ❌ 不会脱敏（不完整）
```

### 2. 字符长度

```
地址：至少 5 个字符
公司：至少 3 个字符

过短的配置会被忽略，避免误伤普通词汇
```

### 3. 处理顺序

```
脱敏按以下顺序处理：
1. 基础脱敏（手机号、身份证等）
2. 姓名脱敏
3. 公司脱敏
4. 地址脱敏

后续脱敏不会影响已脱敏的内容
```

### 4. 性能影响

```
自定义列表越长，处理时间略有增加

建议：
- < 100 条：几乎无影响
- 100-500 条：轻微影响（< 5%）
- > 500 条：考虑优化或分批处理
```

## 📞 常见问题

### Q1：地址脱敏后还能看出大致区域吗？

**答**：可以。脱敏规则保留了地址的前缀部分（如省市区），只脱敏了详细地址：

```
原文：北京市朝阳区建国路88号现代城A座12层
脱敏：北京市朝阳区建******12层
      ↑ 保留省市区信息
```

---

### Q2：公司简称和全称都需要配置吗？

**答**：推荐都配置，以确保完整脱敏：

```
配置列表：
某某科技有限公司（全称）
某某科技（简称）
XX Tech（英文简称）
```

---

### Q3：可以用正则表达式吗？

**答**：当前版本不支持正则表达式，使用精确匹配。如有需求，可考虑以下方案：

```
方案 1：列举所有变体
  某某科技有限公司
  某某科技股份有限公司
  某某网络科技有限公司

方案 2：使用自定义脱敏规则（高级）
  修改 custom_patterns 参数
```

---

### Q4：脱敏会影响 OCR 识别准确度吗？

**答**：不会。脱敏是在 OCR 识别完成后进行的：

```
处理流程：
1. OCR 识别 → 获得原始文本
2. 应用脱敏规则 → 生成脱敏文本
3. 同时保存原文和脱敏文本
```
