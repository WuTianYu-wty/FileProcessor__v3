# 文件夹上传功能说明

## ✨ 新功能

现在支持**上传整个文件夹**，并自动保持原始目录结构！

---

## 🎯 功能特性

### 1. 文件夹上传
- ✅ 支持上传整个文件夹
- ✅ 自动保持原始目录结构
- ✅ 递归上传所有子文件夹和文件
- ✅ 支持深层嵌套的目录结构

### 2. 文件/文件夹切换
- 🔄 界面右上角的开关可以切换模式
- 📁 文件夹模式：上传整个文件夹
- 📄 文件模式：上传单个或多个文件

---

## 📖 使用方法

### 方式 1：使用界面开关

1. 打开"文件上传"页面
2. 点击右上角的 **文件/文件夹** 切换开关
3. 选择"文件夹"模式
4. 点击上传区域或拖拽文件夹
5. 选择要上传的文件夹
6. 点击"开始上传"

### 方式 2：拖拽上传

1. 切换到"文件夹"模式
2. 从文件管理器拖拽整个文件夹到上传区域
3. 点击"开始上传"

## 🏗️ 目录结构示例

### 上传前的文件夹结构：

```
MyProject/
├── docs/
│   ├── README.md
│   └── API.pdf
├── src/
│   ├── main.js
│   └── utils/

└── config.json
```

### 上传后的存储结构：

```
uploads/
└── MyProject/
    ├── docs/
    │   ├── README-1733423456789-123456789.md
    │   └── API-1733423456790-987654321.pdf
    ├── src/
    │   ├── main-1733423456791-456789123.js
    │   └── utils/
    │       └── helper-1733423456792-789123456.js
    └── config-1733423456793-321654987.json
```

**说明**：
- ✅ 目录结构完全保持
- ✅ 文件名添加时间戳后缀（避免冲突）
- ✅ 可以通过数据库的 `relative_path` 字段查询原始路径

---

## 💾 数据库存储

### files 表新增字段

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| `relative_path` | TEXT | 文件的相对路径 | `MyProject/docs/README.md` |

### 查询示例

```sql
-- 查询某个文件夹下的所有文件
SELECT * FROM files 
WHERE relative_path LIKE 'MyProject/%'
ORDER BY relative_path;

-- 查询某个目录的直接子文件（不包括子目录）
SELECT * FROM files 
WHERE relative_path LIKE 'MyProject/docs/%'
AND relative_path NOT LIKE 'MyProject/docs/%/%';
```

## ⚙️ 技术实现

### 前端

1. **模式切换**：
   ```jsx
   <Switch
     checked={folderMode}
     onChange={setFolderMode}
     checkedChildren="文件夹"
     unCheckedChildren="文件"
   />
   ```

2. **文件夹上传**：
   ```jsx
   const uploadProps = {
     directory: folderMode,  // 开启文件夹上传
     // ...
   }
   ```

3. **路径提取**：
   ```javascript
   const relativePath = file.originFileObj.webkitRelativePath || file.name
   formData.append('relativePath', relativePath)
   ```

### 后端

1. **动态创建目录**：
   ```javascript
   const fileDir = path.join(uploadDir, path.dirname(relativePath));
   if (!fs.existsSync(fileDir)) {
     fs.mkdirSync(fileDir, { recursive: true });
   }
   ```

2. **存储路径信息**：
   ```javascript
   const fileData = {
     original_name: req.file.originalname,
     file_path: req.file.path,
     relative_path: relativePath,  // 新增
     // ...
   }
   ```

## 📊 性能考虑

### 文件夹大小限制

| 项目 | 限制 | 说明 |
|------|------|------|
| 单个文件 | 5GB | 每个文件最大 5GB |
| 文件数量 | 无限制 | 但建议一次不超过 1000 个 |
| 文件夹大小 | 无限制 | 取决于磁盘空间和上传时间 |

### 上传时间估算

假设网速 100Mbps：

| 文件夹总大小 | 文件数量 | 预估时间 |
|-------------|---------|---------|
| 100MB | 100 | ~10 秒 |
| 1GB | 500 | ~1.5 分钟 |
| 10GB | 1000 | ~15 分钟 |
| 50GB | 5000 | ~75 分钟 |

**提示**：
- 文件越多，上传时间越长
- 建议将大型文件夹分批上传
- 确保网络连接稳定

## ⚠️ 注意事项

### 1. 浏览器兼容性

| 浏览器 | 文件夹上传支持 | 备注 |
|--------|---------------|------|
| Chrome | ✅ 完全支持 | 推荐使用 |
| Firefox | ✅ 完全支持 | 推荐使用 |
| Edge | ✅ 完全支持 | 推荐使用 |
| Safari | ✅ 支持 | macOS 13+ |
| IE11 | ❌ 不支持 | 不推荐 |

### 2. 文件类型限制

即使在文件夹模式下，仍然会验证文件类型：
- ✅ 支持：.pdf, .doc, .docx, .txt, .wps
- ❌ 不支持：其他类型会被自动跳过

### 3. 上传中断

如果上传中断（网络断开、浏览器关闭等）：
- ❌ 已上传的文件会保留
- ❌ 未上传的文件需要重新上传
- 💡 建议：将大文件夹分批上传

### 4. 空文件夹

- ⚠️ 空文件夹不会被上传（浏览器限制）
- ⚠️ 只有包含文件的文件夹才会创建目录结构

## 🧪 测试建议

### 测试步骤

1. **小文件夹测试**：
   - 创建一个包含 5-10 个文件的简单文件夹
   - 测试上传和目录结构保持

2. **嵌套文件夹测试**：
   - 创建多层嵌套的文件夹结构（3-4层）
   - 验证所有层级都正确创建

3. **大文件夹测试**：
   - 上传包含 100+ 文件的文件夹
   - 检查上传进度和稳定性

4. **混合类型测试**：
   - 文件夹中包含不同类型的文件
   - 验证类型过滤是否正常工作

## 🐛 故障排查

### 问题 1：文件夹选择后没有显示文件

**原因**：浏览器不支持或文件夹为空

**解决**：
- 检查浏览器版本
- 确保文件夹包含支持的文件类型

### 问题 2：上传后目录结构不正确

**原因**：relative_path 没有正确传递

**解决**：
- 检查浏览器控制台是否有错误
- 确认后端日志中包含 relativePath 信息

### 问题 3：部分文件上传失败

**原因**：文件类型不支持或文件过大

**解决**：
- 检查失败文件的类型和大小
- 查看后端日志了解详细错误
